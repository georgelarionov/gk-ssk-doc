# Приложение №3. Состав работ

К Договору № ___ от «___» __________ 20__ г.

Платформа ИИ-агентов «ИИ-хаб» (корпоративная платформа для запуска и эксплуатации ИИ-агентов и бизнес-процессов).

---

## 1. Разработка: Backend

- Серверное приложение (Hono runtime): аутентификация, ролевая модель доступа (RBAC), аудит действий, ограничение частоты запросов (rate-limit).
- Продуктовые API: чаты, треды, история, выбор модели, проекты, процессы, база знаний, справочники.
- Ядро ИИ (Mastra): агенты, workflows, инструменты (tools), долговременная память, RAG.
- Слой данных (PostgreSQL/Drizzle): схемы приложения, RAG-метаданных и аудита; миграции.
- Хранилище документов (S3-совместимое): загрузка, извлечение текста, изоляция парсинга недоверенных файлов.
- Учёт потребления и лимиты (usage/бюджеты) по моделям и пользователям.
- Изоляция рабочих пространств (multi-tenant): разграничение данных по организации и пользователю.

## 2. Разработка: Интеграции

- Подключение каталога LLM-моделей через OpenRouter (выбор модели per-request, кэш каталога, allow-list).
- Реестр коннекторов к внешним системам (тул `external-system-call`) и каркас для подключения корпоративных систем.
- Интеграция с HR-данными (реестр сотрудников, карточка 1С) для сценариев расчёта и чата.
- Импорт/синхронизация данных из внешних источников (1С, Bitrix24) в реестры и базу знаний.
- Почтовые уведомления (отправка писем — сброс пароля, инвайты, ведомости) через внешний провайдер.
- Приём входящих документов в бизнес-процессы (intake) и выгрузка результатов (xlsx-ведомости).

## 3. Разработка: Frontend

- Веб-приложение (React 19 + Vite): единый origin с API, SPA-маршрутизация.
- Чат с ИИ-агентом: потоковые ответы (SSE), история, выбор модели, вложения документов.
- HITL-подтверждения (human-in-the-loop) для опасных действий агента.
- Разделы платформы: Главная (статус сервисов), Чаты, Проекты (командные пространства), Процессы (бизнес-процессы), База знаний, Администрирование (пользователи, сотрудники, настройки организации).
- Аутентификация: вход, восстановление пароля, приём инвайтов.
- Дизайн-система и оформление (тема, типографика, иконки провайдеров моделей).

## 4. Тестирование (QA)

- Модульные и интеграционные автотесты по слоям (API, ядро ИИ, БД, веб).
- Тестирование сквозных сценариев: чат, процессы (расчёт ЗП), проекты, база знаний.
- Проверка ролевой модели и изоляции рабочих пространств (разграничение доступа).
- Регрессионное тестирование при изменениях; статический анализ и линтинг.
- Приёмочное тестирование на стенде заказчика перед вводом в эксплуатацию.

## 5. Развёртывание на сервере заказчика

Поставка и настройка платформы на инфраструктуре заказчика. Состав разворачиваемых сервисов:

| Сервис | Назначение |
|--------|------------|
| **Приложение «ИИ-хаб» (API + Web)** | Бэкенд и веб-интерфейс одним процессом/контейнером; обслуживает все запросы пользователей. |
| **PostgreSQL (+ pgvector)** | Основная база данных: данные приложения, аудит, память агентов, векторный индекс для RAG. |
| **Redis** | Кэш, очереди задач, потоковая шина событий (live-логи процессов). |
| **S3-совместимое хранилище** | Хранение загруженных документов и сгенерированных файлов. |
| **Ядро ИИ (Oneclick Core AI / Mastra)** | Исполнение агентов, workflows, инструментов и памяти (в составе приложения). |
| **Доступ к LLM-провайдеру (OpenRouter)** | Внешний доступ к языковым моделям; требует исходящего интернет-соединения либо согласованного шлюза. |

Работы по развёртыванию включают:

- Настройку окружения и переменных конфигурации (доступы к БД, Redis, хранилищу, провайдеру моделей).
- Применение миграций базы данных и первичное наполнение справочников (seed).
- Настройку доменного имени, TLS и health-проб.
- Проверку готовности инфраструктуры (readiness: БД, Redis, хранилище, ядро ИИ, модели).
- Передачу доступов и краткую эксплуатационную инструкцию.
